Experiment 1 — Speech-to-Text

STT: Original Results & Recommended Tools

Three tools were originally tested. Only faster-whisper has multilingual support, but it failed on Bangla because the language parameter was not explicitly set. Below shows the original results and the corrected tool selection.

Original Run — Tool Selection Problem
Why the original tools are inadequate

pocketsphinx: English-only acoustic model shipped; no multilingual support; max ~71% accuracy even on clean English.

Key finding — Bangla STT
Whisper large-v3 with explicit language="bn" corrects the original 0% failure but still produces errors on technical vocabulary (7.7% on S5). The Bangla fine-tuned model bengaliAI achieves 100% on both BN inputs, demonstrating the value of domain-specific fine-tuning for low-resource scripts. For general use, combining Whisper (EN/HI) with bengaliAI (BN) gives full trilingual coverage.
Engineering note — ffmpeg dependency
The transformers ASR pipeline calls ffmpeg when given a file path. Fix: load WAV with soundfile as a float32 NumPy array and pass {"array": audio, "sampling_rate": 16000} dict to the pipeline. bengaliAI model has an outdated generation_config — omit generate_kwargs={"language": ...} when loading the pipeline.

The original tools (Wikipedia API, Keyword Extractive, Wikidata) are retrieval-only pipelines — no neural multilingual QA. They do not handle Bangla/Hindi QA adequately and miss "father of" or yes/no question types entirely.

Key finding — Machine Translation
M2M100 correctly handles simple short sentences (BN→EN, HI→EN both 100%) but degrades on complex technical text — EN→HI 50%, BN→HI 46.2%, due to semantic drift across two script changes. Helsinki-NLP en-hi also struggles with technical vocabulary (7.1% RT) versus its strong short-sentence performance (100% HI→EN). For cross-script technical translation, NLLB-200 is expected to outperform both.
