1(a) — NFA for searching {wed, led, vowed, vowel}2 marks

Read literally, part (d) asks whether the string "vowed" contains "wed" — so this is a search automaton: given any text over Σ = {v, o, w, e, d, l}, it should detect any of the four words occurring anywhere inside it. This is exactly the shape of the class's own "web, well, wet, wait" search-NFA exercise: a trie of the patterns, plus a self-loop on the start state over the whole alphabet so a fresh match attempt can begin at every position in the text. States are numbered q0, q1, q2, … in the order they're created, same as the lecture.

No invalid state here: every state has a transition on every symbol (q0's self-loop absorbs anything that doesn't start a new pattern), so the automaton is already total — a search machine has no "invalid input," only "no match found yet." An invalid state becomes necessary only for the validators in Q2/Q3 below.

1(d) — Does "vowed" contain "wed"?2 marks

Trace the DFA on input v o w e d:

A--v--> B--o--> E--w--> H--e--> K--d--> L = {q0, q8, q11} — Valid State

Yes. L is a Valid State and its subset contains q8 (the Valid State marker for "wed") alongside q11 ("vowed") — the DFA recognises "wed" as a substring of "vowed" (positions 3–5) at the exact moment it also completes the full match of "vowed".

2(i) — DFA for a valid MSCSE student ID5 marks

Format: 012.YY.T.RRR → 9 digits total. Fixed literal prefix 012, YAD = any 2 digits, TAD ∈ {1,2,3}, ROLL = 3 digits that must not all be zero. This mirrors the class's own MSCSE-ID DFA exercise (18 July lecture) exactly in technique: a literal-prefix chain, then digit-counting states, then a branch into a Valid State / Invalid State pair with the Invalid State self-looping on every symbol.

Verified independently — bug found and fixed
The first version of this DFA only consumed 2 of ROLL's 3 digits (it decided Valid/Invalid one digit too early), so no 9-digit ID could ever reach the Valid State. Fixed by giving ROLL its own 5-state sub-chain (q7→{q8,q9}→{q10,q11}→{Valid,Invalid}) that correctly consumes all three digits before deciding — states renumbered sequentially q0–q13 below, matching the lecture's plain-numbering style.

Dashed arrows → q12 (Invalid State): wrong literal digit at q0/q1/q2, non-digit or wrong class anywhere, TAD ∉ {1,2,3}, ROLL's 3rd digit = 0 when the first two were also 0 (i.e. ROLL="000"), or any extra character after the Valid State (this enforces the length is exactly 9). q12 self-loops on every symbol — once reached, it can never be left.

Regular expression for the ID (course notation)

RE = 012   DD   (1/2/3)   DDD,   where D = 0|1|2|…|9

Same field widths as the class's own "MSC ID – RE" derivation: literal 012, then DD for YAD, (1/2/3) for TAD, DDD for ROLL. Shorthand: 012[0-9]{2}[1-3][0-9]{3} — the "ROLL ≠ 000" rule is a semantic constraint the plain regex can't express, which is exactly why the DFA above needs the extra q7–q11 branching.

2(ii) — DFA / regex for valid UIU email addresses5 marks

Only five domains appear as valid in the exam's own list: cse.uiu.edu, uiu.edu, cse.uiu.ac.bd, uiu.ac.bd, gmail.com — while mscse.uiu.edu, mscse.uiu.ac.bd, and hotline.com are listed as the invalid ones ("mscse" ≠ "cse"; "hotline.com" ≠ "gmail.com"). The local part (X, Y, Z, W, S) follows the pattern in mnh, Nurul.Huda, huda73bd, Nurul_Huda: starts with a letter, then letters/digits, with single . or _ separators between alphanumeric runs.

3(a) — Regular expressions4 marks

Matches the class notes (18 July lecture, "Regular Expression" section) exactly
The lecture defines D = 0|1|2|…|9 and gives the integer regex as (ε|+|−)DD*, and the decimal-number regex as (ε|+|−)(D⁺ | D⁺.D⁺ | .D⁺) — which explicitly allows a leading-dot number like ".53" with nothing before the point, and places no restriction on leading zeros.

i. Positive or negative integers

RE = (ε / + / −) D D* ,   where D = 0|1|2|…|9
[+-]?[0-9]+

ii. Positive or negative real numbers

RE = (ε / + / −) ( D⁺.D⁺ / .D⁺ ) ,   where D = 0|1|2|…|9
[+-]?([0-9]+\.[0-9]+|\.[0-9]+)

A decimal point is mandatory; the integer part before it is optional (".56" is valid on its own, matching the lecture's decimal-number DFA where the start state has a direct '.' transition into the fractional branch). At least one digit after the point is always required.

iii. Private university names {DIU, UIU, USTC, UITS, AUST, AIUB, IUB}

RE = DIU / UIU / USTC / UITS / AUST / AIUB / IUB

A closed set of literals — plain alternation, no repetition needed.

iv. 17-digit National ID

Bangladesh's Smart NID is a 17-digit number for citizens registered 2007 onward: the first 4 digits are birth year, followed by a 13-digit unique serial (per the Election Commission's published format).

RE = (1/2) (9/0) DD   D D D D D D D D D D D D D   (13 digits),   where D = 0|1|2|…|9
(19|20)[0-9]{2}[0-9]{13}

If only the fixed length matters and the birth-year constraint isn't required: RE = D repeated 17 times, i.e. [0-9]{17}.

3(b) — DFA for the mini assignment-statement language4 marks

Given: sum=a+b;  a=9;  sum=a+9.5;  b=9.467;  sum=9.5-b; — the grammar is VAR = operand (op operand)? ; where operand is VAR or NUM, and op is + or −. This mirrors the class's own "Sum = a+b" DFA exercise (18 July lecture) — same branching after "="; NUM here follows the D⁺ | D⁺.D⁺ | .D⁺ form from 3(a)(ii). VAR/NUM are their own small sub-DFAs; a character outside a token's class hands control back to the dispatcher (maximal-munch tokenising), while anything illegal everywhere goes to a shared Invalid State.
